定于 2026-10-05（口径由用户拍板；同日多次修订，依据 `exp/数据核查记录.md` 的核查结论）。
本规范同时约束三件事：参照解析怎么标、智能体解析结果怎么判、验证报告怎么呈现。
凡本规范与开题报告的技术指标冲突，以本规范为准。

> **与 `kb/` 的分工（v4 明确）**：本规范是**判定口径**（怎么标、怎么判、怎么呈现），
> 面向人；`kb/解析规则.md`（R1–R16）是同一批知识的**面向智能体的形式**（可进提示词、
> 可被检索），`kb/术语与省略写法.md` 是省略写法对照表（W8 的落点）。
> 规则增删只改 kb，判定口径变更改本文件；两处的规则编号（R8 等）互相对应。
> `data/README.md` 是逐件留档，**不进提示词**（是答案不是规则）。

> 口径分工（v2 明确）：**参照解析集**（输出轴、铜套 2 件）只服务「解析准确率」；
> 几何验证不依赖它——几何验证是「重演末态 vs 成品模型」的重演比对，正常与异常样本
> 一视同仁，不需要金标准。故 2 件足够，不必标 10 件。

## 一、粒度：一条工序算一次

解析、判定、统计的单位都是**工序**，不是工步，也不是去除体。

- 一条工序里哪怕写了好几个动作（如输出轴工序 3「车右端面 + 钻中心孔 + 粗车右端各部」），
  也**只算这一条工序**，不拆开计分。
- 数据结构上，一条工序记录挂在若干**去除体**（几何上仍要逐步布尔差），但比对与计分
  时整条工序一起判：这条工序对，就是对的。
- 后果：正确率的分母 = 数据集中「去除类工序」的条数；非去除类工序不入分母。

## 二、工序分类与处理

| 类别 | 例 | 处理方式 |
|---|---|---|
| 去除类 | 车、粗车、精车、铣、钻、磨、半精磨、精磨、钳、线切割、攻丝 | 解析 → 重演 → 一致性检查 → 附图 → 验证结论 |
| 非去除类 | 热处理、冷处理、划线、检验、入库、下料、锻造、探伤、标记 | 报告里**原样照抄**工序号 + 名称 + 内容原文，不生成附图、不给验证结论 |
| 准去除类 | 铜套工序 4「拉深 0.5mm、长 24mm 润滑槽」 | 按环形槽用布尔差表达（与成品模型一致），归入去除类 |

`kind` 的判据是**几何是否改变**：独立成序的「钻中心孔」按 R3 记 `neutral`（几何上不建，
入不了分母）；并进车序里的中心孔随该序记 `removal`。热处理 / 划线 / 检验 / 入库 / 下料 /
锻造 / 铸造按上表记 `neutral`；「拉深润滑槽」随所在工序记 `quasi_removal`（归入去除类）。

非去除类在报告中的呈现固定为一句说明，例如：

```
工序 2  热处理  调质处理 28 ~ 32HRC
        本工序不改变工件几何，不生成附图与验证结论。
```

## 三、数值缺省的处理（四级优先）

1. **文本直接给了数** → 用它。绝大多数工序属于这一类。
2. **「至图样尺寸 / 按图样」但同句给了数** → 用该数。例：连杆螺钉工序 13「磨 φ34.5mm
   尺寸至图样要求 φ34(-0.016/0)mm」→ 目标是 φ34。
3. **粗加工的工艺性描述** → 先看句子里有没有给数，给了就用那个数：
   - 「见平即可 / 见圆即可」：**有数用数**（去黑皮，该数与其他尺寸无关）。
     例：输出轴工序 3「φ88mm 见圆即可」→ 目标是 **φ88**（毛坯 φ90 只是上限，不是目标）。
     若句子里没给数（如齿圈工序 4「车端面，见平即可」）→ 目标 = 把毛坯端面车光，不给尺寸。
   - 「留精加工余量 Xmm / 留磨削余量 Xmm」→ 目标 = 成品尺寸 + X（活塞杆写明「直径方向
     留加工余量 1mm」时，直径加 2X）。
4. **文本缺值、但成品模型有** → 智能体调用几何查询工具从成品量取补全。
   例：输出轴 φ70 两段与键槽（表 4-2 工序 3~10 只说「各部」没给数，图 4-2 尺寸链 85|77|75|
   10|78|20|35=380、A–A 73、B–B 47.5 可查）；铜套工序 4、5 的「倒角」没写 C 值，成品为两端 C1。

四级都补不出来 → 记为**待确认项**，不计对也不计错，在报告里单独列出；人工确认后可回填。

### 三·补 螺纹段直径的口径（v2 新增，源自定义条 1）

规程给螺纹段直径时，给的往往是**车螺纹 / 套螺纹之前的坯料外径**，不是名义大径：

| 工件 | 规程写法 | 书里的证据 |
|---|---|---|
| 阀螺栓 | 工序 3「外径 φ19.7~19.85mm」 | p114 工艺分析 2：套螺纹前坯料外径；普通车床车螺纹时取 φ19.8~φ19.85 |
| 连杆螺钉 | 工序 11「车螺纹部分至 φ30(+0.25/+0.15)mm」 | 工序 12 才是「车螺纹 M30-6g」；p117 工艺分析 5 |
| 接头 | 工序 2「车 M27×2-6g 螺纹外径至 φ27(−0.026/−0.206)mm 长 16mm」 | 表 4-8 原文 |
| 活塞杆 | M39 段「直径方向留加工余量 1mm」 | 表 4-4 原文 |

处理：模型一律按**名义大径**建（M39→φ39、M30→φ30、M27→φ27、M20→φ20、M8→φ8），
上述数值登记为**工艺中间尺寸**，**不参与 0.1mm 偏差判定**，也不算「规程漏写」。
据此，`exp/audit_dims.txt` 里 B 类的「活塞杆 φ39」「阀螺栓 φ20」不是异常。
同理，齿轮只做到**齿坯**（不建齿廓）：齿顶圆是有效外圆（齿圈 d_a = 615 = 图样外圆），
分度圆 / 齿根圆是参考尺寸，不参与几何比对。

### 三·补2 未注倒角 / 未注圆角的记录范围（v6 提出，v7 定案）

倒角在规程文本里有三种出现方式，记录的规矩不同：

| 文本里的样子 | 例子 | 记法 |
|---|---|---|
| 说了「倒角」但没给 C 值 | 铜套工序 4/5「倒角。」；齿圈工序 7「各部倒角 C1」而成品另一端还有 C2 | 按第 4 级从成品量取，写进 `items`（`what: "chamfer"`、`source: "geometry"`、`must_call_tool: true`） |
| 给了 C 值 | 阀螺栓「倒角 C1」、活塞杆「倒角 C2」、调整偏心轴「倒角 C1」 | 写进 `items`，`source: "text"` |
| **整条规程没提过「倒角」** | 定位销轴 φ20 端面 C1、输出轴两端 C2、连杆螺钉 φ34 段两端 C1（成品上确有其圈） | **同样按第 4 级从成品量取**，写进 `items`（`source: "geometry"`、`must_call_tool: true`） |

第三行曾按 v6 的过渡口径「暂不写进 items、待统一」。**2026-10-05 定案：统一到第 4 级**
（用户拍板）——判据只看两条：**成品上量得到** + **本条工序内容没给值**。理由：模型上确实有这
一圈倒角，不写进 items，重演时它无处安放，与 `data/README.md` 把「未注倒角」列为缺值项的口径
也矛盾。据此连 2 件参照解析一起改了（输出轴 op5/op6 各补 C2、定位销轴 op4 补 C1）。

**落位规则**：记在**车出该部位的那道工序**上（倒角是车出来的，不记在磨 / 铣序上）；同一条工序
里同一 C 值出现在两处（如连杆螺钉 φ34 段两端），按既有惯例（铜套 op4/op5、活塞杆 op16/op17
都是两处倒角记一项）记**一项**，位置写在 `note` 里。

**同一条规则也用在圆角上**：连杆螺钉 op11 按图 4-7 补记头部过渡 R2、φ34 段两端根部 R1
（`what: "radius"`）与 φ34 段两端 C1——三者都是本序车出、而工序内容未给值。反过来，模型上
**不存在**的特征不记：图 4-7 的螺纹收尾 R0.5 因 R1（螺纹按大径车成光圆柱）在模型上无处安放，
只在 `size.note` 里说明，不写进 `items`。

第 3、4 级正是开题报告 4.2「允许智能体调用几何查询工具」的用途——粗加工尺寸、未注倒角与
未注圆角不靠猜，靠毛坯与成品模型的实测几何。

## 四、工序记录的字段（process_plan.json）

落在 `exp/plans/<工件>/process_plan.json`。**一份契约三处共用**：① 将来让外部 LLM 严格 JSON
结构化输出的目标 schema（`src/process_plan.schema.json`）；② 判分器读参照解析的输入契约；
③ 人工录入格式。校验器 `src/check_plan.py` + 零依赖 `src/plan_schema.py`。

| 字段 | 说明 |
|---|---|
| `no` / `name` / `text` | 工序号、工序名称、工序内容原文（原样保留，不改写；校验器逐行字节还原核对） |
| `kind` | `removal` / `neutral` / `quasi_removal`（判据见 §二） |
| `method` | 加工方法（车 / 精车 / 磨 / 铣 / 钳 …）。**本阶段不冻结枚举**，由校验器汇总成方法清单，W6 交出去前再冻结 |
| `target` | 加工部位（如「右端 φ60 外圆」「内孔」「两端面」）。`neutral` 工序为空 |
| `size` | `{"items": [...], "note": ""}`，子结构见 §四·补 |
| `datum` / `fixture` | 基准、装夹方式（未写明就写空串，不猜） |
| `source` | 数值依据：`text` / `blank_minus_allowance` / `geometry` / `pending`。**取本工序各目标里最高的缺省级别**（第 4 级 geometry > 第 3 级 > 第 1/2 级），因为它决定"这条是否必须调几何工具" |
| `bodies` | 去除体列表（几何重演用）。**W2 阶段必须为空数组**，校验器硬断言 |
| `not_modeled` | 几何上不体现的理由，只准填 `R1`–`R7`（螺纹牙型 / 齿廓 / 中心孔 / 微去除 / 毛坯取法 / 连下件 / 工艺凸台）。这是"不体现"的**唯一**豁免字段，写在 plan 里，`grade.json` 不重复 |
| `pending` | 待确认项说明（无则空） |

**plan 里不写 `counts`**：工序条数、去除类条数（正确率的分母）等一律由 `check_plan.py` 算出、
写进 `exp/plans/index.json`——手写的数字只会漂移。

### 四·补 `size.items[]` 子结构

| 字段 | 说明 |
|---|---|
| `what` | `dia` / `len` / `width` / `depth` / `radius` / `chamfer` / `angle` / `pos` |
| `value` | 数值（mm 或度） |
| `tol` | `[下偏差, 上偏差]`；文本未给公差则**不写这个键**（不要写 null） |
| `role` | `final` 终序尺寸 ／ `intermediate` 工序链中界面（螺纹段坯料外径 R9、留余量后的车削尺寸）／ `stock` 只车光（「见平 / 见圆即可」且句中给了数） |
| `source` | 逐项覆盖工序级 `source`；一句话里混了两种来源时**必须逐项标** |
| `must_call_tool` | 该项是否**必须**调几何工具才能拿到（判分器据此把「量出来的」与「猜对的」分开） |
| `note` | 依据说明（可选） |

- 文本缺值的项（如输出轴键槽长 73 / 深 6.9）标 `source: "geometry"` + `must_call_tool: true`。
- 「见平 / 见圆即可」**句中没给数**的：该项**不写进 items**（不写 0、不写 null），由判分块的
  `required` 表达"允许没有"。

**`not_modeled` 在校验器里的粒度是"逐项"**（v6 记「整条工序」，v7 改）：C 项几何强校验只查
`role = "final"` 的条目；某条 op 声明了 `not_modeled` 时，该 op 里**成品上查得到的项照常记
`verified`，只有查不到的才记 `exempt`**（豁免）。v6 的做法是整条工序一起豁免，代价是**该 op 的
其它终值尺寸也一并失去几何校验**——`定位销轴` 一度是豁免 13 / 实测 0（R3 恰好落在它两条载有真实
尺寸的工序上），等于这件没有几何校验。改成逐项后，同一份录入变成实测 6 / 豁免 0。豁免项
**逐项列名**在 `exp/check_plan.json` 的 `geometry.exempt_values` 里，可见、不隐藏。

豁免分支不是死代码，两条路都验过：往某条声明了 `not_modeled` 的工序里塞一个成品上不存在的
直径 → 不报错、`exempt +1` 并列名；把同一条工序的 `not_modeled` 撤掉再塞同一个值 → 报 ERROR。

### 四·补2 判分块（`grade.json`，只有参照解析集有）

| 字段 | 说明 |
|---|---|
| `graded` | 入不入正确率分母。恒等于 `plan.kind != "neutral"`（校验器核对） |
| `kind` / `method` / `method_ok_alt` | 期望类别与方法；`method_ok_alt` 给同义写法（如「粗车」之于「车」） |
| `target_terms` | 期望出现在该工序里的词，**词表命中**即可（不要求字符串相等，避免把表述差异判成解析错） |
| `targets` | 期望目标值：`what` / `value` / `tol_mm` / `allowed_sources` / `must_call_tool` / `required` |
| `expected_tool_use` | `none` / `optional` / `required`：该工序整体是否需要调几何工具 |
| `ambiguity` | 该工序命中的省略写法（与 `exp/ambiguity_hits.json` 对账） |

**W6 判分算法**（本节即契约，W6 实现）：按 `no` 对齐 → 逐项比 `kind`（严格）、`method`（归一化后
含 `method_ok_alt`）、`target_terms`（词表命中）、`targets`（值按 `tol_mm` 比）、
`source ∈ allowed_sources`。**一条工序全部子项对才算这条对**（粒度：一条工序算一次，§一）→
正确率 = 对的条数 ÷ `graded_total`。若 `must_call_tool = true`（或 `expected_tool_use = required`）
而外部 LLM 的调用轨迹里没有几何工具调用，该条即使数值对也另计为 **`guessed`（"猜对"）**，
**与正确率同屏报出**——否则首轮 60%~75% 会被误读成模型能力，其中可能有相当比例是猜对的。

## 五、已知的规程文本问题

1. **铜套外圆是 φ39（不是 φ35）**：**数据集里的规程文本已写作 φ39**(+0.076/+0.060)，
   与成品模型一致，读文本时不要再按 φ35 理解。出处：书上原表 4-11 此处写作
   φ35(+0.076/+0.060) 是笔误（φ35 是内孔，若作外圆则壁厚为 0），而书 p124 图样分析
   自己给出的是「φ35(+0.041/+0.025) 与 φ39(+0.076/+0.060) 的同轴度」。
   这是**数据集文本与书上原表唯一的有意偏离**（见 `data/README.md` §五）。
   相关的 φ36 不必另行说明：工序 4「拉深 0.5mm、长 24mm 润滑槽」→ 槽底 φ36 = 35 + 2×0.5，
   成品里 5~29 段即 φ36，由文本即可推出。
2. **齿圈毛坯尺寸书上没给**：表 4-34 工序 1 只写「铸」，未给铸件尺寸。模型按工序 4/5
   粗车后的「φ620 / φ545 × 厚 45」取值（粗车尺寸本身就是毛坯的最近一档），
   docstring 已注明。
3. 少数非标写法集中在**粗加工工序**（见平 / 见圆 / 各部 / 留余量），均按第三节第 3 级处理，
   不视为歧义。
4. 数据集已经过 2026-10-05 全面核查（`exp/数据核查记录.md`）：**真错只有活塞杆右端母线**
   （漏 1:20 锥面、φ36 切槽长度写成 60），已修已复验；其余 9 件模型与文本、书上原图原表三方一致。

   终值 **4.0**，与成品模型一致。4.5 是工艺中间尺寸，不是与 4 矛盾。
2. **定位销轴小头段**：工序 5 只写「车小头 φ15mm 处锥度」，没给轴向尺寸 → 按第 4 级
   从成品量取（锥面 φ18→φ15 长 3.5、φ15 平头 1.5）。

规矩外的**逐件口径**（毛坯怎么取、哪些文本缺值要靠几何量取、哪些工序在模型上不体现）
