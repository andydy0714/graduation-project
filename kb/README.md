# 解析知识库（kb/）

**给解析智能体看的知识**——提示词 / 检索增强的素材（W8「规程术语检索增强」的落点）。
`data/` 是数据集本体（STEP + 工艺规程），`kb/` 是"怎么读规程"的领域知识。三者一起构成
系统的输入；`data/README.md` **不在此列**（见下"边界"）。

| 文件 | 内容 | 消费者 |
|---|---|---|
| `解析规则.md` | 模型语义（R1~R7）、数值口径（R8~R13）、系统契约（R14~R16） | 解析智能体提示词 / 检索 |
| `术语与省略写法.md` | 「见平即可」「按图样」「各部」「倒头」…这类写法的读法 | 同上 |
| （后续 W3）`几何查询工具契约.md` | 智能体可调的只读几何工具的入参/返回 | 工具调用说明 |

## 边界：什么能进 kb，什么不能

唯一的标准问题：

> **把这条用到一件没见过的新零件上，它还能指导解析吗？**

- **能** → 是规则，进 `kb/`。写"螺纹按名义大径""文本缺值调几何工具量取"。
- **不能**（它说的是"本件是什么"）→ 是**答案**，只能进 `data/README.md` 留档，
  **不得进提示词、不得进检索库**。比如"某件 φ70 两段各长多少""某件槽距端面 4mm"。

为什么要把这条分界写死在 README 里：一旦答案混进提示词，模型就不是在解析规程，
而是在查表——解析准确率会虚高，而这个数字是毕设要报的东西之一。宁可规则少、要抽象，
不可规则里夹带具体工件的数值。

**注意**：具体工件的数值不是"不能用"，而是**要由系统自己量出来**——
文本缺值时调 `geotools` 从成品 STEP 量取（规则 R8），这条路径才是要验证的能力。

## 来源与适用范围（重要）

- 规则由**10 件正常样本**归纳（2026-10-05），因此**尚未证明普适**：它们可能过拟合这 10 件。
- 验证办法：留出集（另取零件、不为其写任何说明）跑一遍，看规则够不够、会不会误报。
  在留出集上跑过之前，R1~R16 都只能算"待验证的假设"，不是已验证的结论——报告里也要这么写。
- 新增规则时先问上面那个标准问题；若某条规则只对某一类零件成立，要写成**前置条件**
  （如"管螺纹建锥面"而不是"接头建锥面"）。
- 命中规则 = 有依据的解析；**没命中规则 = 必须报待确认**（R15），不许默认取值。
